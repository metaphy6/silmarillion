# Runtime content extraction — revision 6

`src/content/factions.json` is a derived runtime input, not a replacement gameplay authority. The owning sources are `docs/design/silmarillion-game-report.md` revision 6 and `hero-balance-roster.json`; presentation comes from `docs/design/art-direction/faction-matrix.json`. Existing roster power prose and identifiers must remain intact. Four hero input files contain 53 entries; the current roster adds the two mutually exclusive Melkor doctrines for 55 profiles and 54 factions.

## Contract

The top-level `profiles` array follows the authoritative roster order. Every entry preserves exact `id`, `faction` and `hero`. `identity` is the profile ID except both Melkor doctrines share `melkor`. This field is not authorization to make multiple versions of a named character. `recipe` has `code`, four-stock `cost` and `turns`; human recipes use their exact profile ID as their code because the report does not assign them a letter. Hero prices exclude the additional component. `component.cost` and `.turns` specify ordinary component production, with the independent missing-source fallback under `sharedRules.componentSynthesis`.

`heroBuilding`, `facilities`, `production`, `magicEquipment` and `weakness` preserve distinct faction institutions, ordinary products, research/equipment themes and vulnerabilities. Production and magic strings are source descriptions; they do not themselves implement additional powers. In particular, `magicEquipment` may contain the row's stated specialty/weakness when the source table uses that heading. Use the structured hero roster for actual abilities.

`caps` records source numeric limits. Null means unspecified, never unlimited. `supportPlots` excludes the core. Dark Architect's initial eight plots belong to his Black Citadel; each additional Fortress Hold has six, adds twelve supply and two great-creature points, within three cities and 60/8 overall maxima. Its `cities:3` is the permitted maximum, not three free starting cities. `anchors:3` is the global hero maximum; Melian's major Girdle uses two. Starting binding is two; each ordinary summon also consumes ordinary supply. Dragon/Balrog recipes use their explicit great-creature cost instead of ordinary binding slots.

`presentation` contains decorative family colors and material/domain descriptions copied from the art matrix. Colors cannot replace semantic accessible UI tokens. These descriptions are invented presentation anchored to the game; they are not assertions of canonical Tolkien institutions. `loreStatus` preserves that distinction.

## Adopted prototype values versus provisional gaps

Hero recipe counts are D=16, A=18, E=8, C=6, B=4, plus one each for Gondor, Rohan and Númenor. D counts both Melkor profiles but only fourteen Valar and one Melkor identity. These are adopted prototype prices, not demonstrated balance.

The report explicitly leaves detailed ordinary building/unit/equipment costs, duration, upkeep, workforce, housing and most capacity increases to tuning. These must be recorded as provisional runtime decisions when implemented. Generic recipe inference must not turn a research theme into a free ability. Hero progression has three role-specific branches in prose but no complete numerical perk tree; a runtime needs a disclosed provisional implementation.

Most components have a name and the instruction to use fitting material/habitat access, but no enumerated source tag. The derived `component.access` supplies an explicitly provisional material interpretation for those entries. The five generic and five named Istari have explicit source access, as does Yavanna's living grove; those mappings are marked adopted. The fallback synthesis always remains available. No component interpretation confers source access for other recipes.

The report does not specify general ordinary queue/city limits for all economic factions; Sauron's industrial exception and Hobbit supply do not receive an explicit dedicated numeric ceiling. Their relevant fields remain null so runtime defaults can be labeled provisional instead of falsely attributed to the report. Caps given for named Istari do not silently become adopted generic-Istari colony limits.

`melkorCreatures`, `callOfTheDark`, `broodDiscipline` and `resonantSentinel` preserve special exact recipes, activation conditions, capacity reservations and upkeep. Siege-brute upkeep is null because the table does not provide it. A runtime must enforce existing-entity travel/discovery and exclusive allegiance beyond these data declarations. The Sentinel maximum is one active or pending instance, and its queue must be staffed with a reserved berth. Dismantling returns no materials. Low upkeep disables interception without changing ownership.
